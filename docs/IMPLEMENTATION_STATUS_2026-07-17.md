# VoiceType Local — статус реализации на 18 июля 2026

Этот файл фиксирует фактическое состояние текущего исходного кода. Он нужен для
переноса проекта между чатами и компьютерами без восстановления контекста по
истории разговора. Этот код собран и 18 июля 2026 года установлен как локальный
candidate с сохранённой предыдущей версией для отката.

## Что реализовано

- Правый Ctrl и режим `нажал — включил / нажал — выключил` сохранены по
  умолчанию; доступны безопасные альтернативные клавиши и режим удержания.
- Режимы `Обычный`, `Диктовка` и `Управление`. `Обычный` соответствует
  смешанному режиму: общая Windows-команда начинается только с точного
  префикса `команда / command / comando`, а остальная речь печатается как
  текст. Исключение — два подтверждаемых действия в конце диктовки.
- Точные действия в конце диктовки на RU/EN/ES: `нажать Enter / press Enter /
  pulsa Intro` и `отправить сообщение / send message / enviar mensaje`. Текст
  вставляется первым, действие удаляется из текста и требует отдельного
  подтверждения; смена поля, ошибка вставки или отмена блокируют действие.
- Строгий RU/ES/EN parser без LLM, shell, произвольных путей, URL и командной
  строки.
- Открытие только известных приложений, переключение/состояние окон, прокрутка,
  безопасные клавиши, нажатие UI Automation элемента по имени или номеру.
- Номерной слой и справка команд не забирают фокус; снимки содержат только
  краткоживущие immutable-дескрипторы и очищаются после hide/cancel/TTL/exit.
- Чувствительные кнопки, ссылки, пункты меню, `Space`, `Enter`, удаление и
  закрывающие сочетания требуют отдельного подтверждения.
- Подтверждение одноразовое, действует 45 секунд и связано с исходным окном,
  snapshot, элементом либо foreground-окном для клавиши. Смена target означает
  отказ.
- Cancel/Escape инвалидирует pending и поздний результат через cancellation
  epoch; locks не удерживаются во время медленных UIA-вызовов.
- UIA/SendInput блокируются для terminal/admin/elevated или неизвестного
  foreground; сам elevated VoiceType не получает Control-capability.
- Команды диктовки `новая строка`, `абзац`, `таб`, знаки препинания на RU/ES/EN;
  URL, email, числа и код защищены от преобразований.
- Бережная локальная коррекция, исходный и финальный текст, повторная вставка,
  копирование и очистка текущей сессии. Постоянной истории нет.
- Подтверждённый тёмный интерфейс варианта №3: шесть рабочих страниц
  `Главная`, `Речь`, `Текст`, `Приватность`, `Доступность`, `О программе`, три
  крупные карточки режимов, языки, способ записи, клавиша и микрофон.
- На `Главной` показывается ограниченная по длине RAM-цепочка `услышано → текст
  → команда → результат`. Она обновляется во время работы, не записывается в
  журнал и исчезает вместе с процессом. Компактная прокрутка сохраняет доступ к
  нижним действиям на небольшом экране.
- Настройки и DPAPI-ключ сохраняются с rollback: сначала создаются candidate
  providers/hotkey, запись настроек copy-on-write, затем runtime swap. Облачный
  режим нельзя включить без существующего или нового ключа.
- Повреждённый, не-object или слишком большой `settings.json` безопасно даёт
  локальные настройки по умолчанию.
- `uiautomation==2.0.29` закреплён; добавлены import-only packaged self-test,
  PyInstaller metadata/hidden imports и отдельная проверка Control-модулей.
- Добавлены поэтапные метрики задержки и единый общий deadline распознавания:
  повторное восстановление worker расходует оставшееся время, а не получает
  новый полный timeout. Для короткой фразы предел ожидания теперь около 30
  секунд вместо потенциально последовательных ожиданий по 90 секунд.
- Реализовано безопасное редактирование только последней подтверждённой вставки
  VoiceType в том же поле: удалить последнее слово, предложение или всю
  вставку; заменить последнее слово, предложение либо единственное точное
  совпадение; вернуть одно последнее исправление. Полное удаление возвращается
  только одноразовой RAM-транзакцией после доказанного пустого DocumentRange и
  точного UIA RuntimeId. Состояние живёт не более 10 минут только в RAM и
  сбрасывается при неопределённом результате.
- Редактор перед каждым действием проверяет исходное окно и UIA RuntimeId,
  положение курсора, точные границы, текст и единственность совпадения. Он не
  использует clipboard, Ctrl+Z или слепые серии Backspace. Пятисекундный
  watchdog не позволяет зависшему UIA-провайдеру удерживать приложение.
- Список микрофонов загружается в фоне и single-flight, поэтому зависший native
  вызов больше не замораживает окно настроек. На экране языка поясняется, что
  фиксированный RU/EN/ES обычно быстрее Auto.
- Каждый пакет Unicode `SendInput` при голосовом редактировании заново проверяет
  generation и target/focus непосредственно перед системным вызовом. Если
  фокус ушёл до первого пакета, не отправляется ни одного события; если это
  произошло между пакетами длинной замены, следующий пакет блокируется, а
  состояние помечается неопределённым.
- Для Chromium `TextRange.Select()` считается только запросом: точный диапазон
  сначала проходит `ScrollIntoView`, затем до 500 мс проверяется через
  `GetSelection`; один проигнорированный браузером запрос можно повторить один
  раз после новой проверки текста, фокуса и RuntimeId. Без доказанного
  выделения `SendInput` не вызывается.
- Очистка текущей сессии теперь сразу удаляет локальные копии и видимый последний
  результат из уже открытого окна настроек и отключает действия повтора/копии.
  Пустой runtime feedback также больше не оставляет старый текст на экране.
- Если очистка совпала по времени с фоновым session-edit, его generation сначала
  инвалидируется. Поздний worker не может вернуть текст в RAM/feedback, а
  возможное уже начавшееся изменение поля честно помечается неподтверждённым.

  change, replay, executor TTL, stale snapshot, cancel epoch, UIA cleanup,
  transactional settings/secret rollback и packaging preflight.

## Производительность: локальный замер 18 июля 2026

- Полный цикл от остановки записи до вставки текста: **p50 3 308 мс**,
  **p95 4 541 мс**, максимум **6 422 мс**.
- Главное узкое место — Whisper: **p50 3 093 мс**, **p95 4 328 мс**,
  максимум **6 140 мс**. Отклик горячей клавиши составил p50/p95 **53/58 мс**,
  коррекция — 22 мс, вставка — 96 мс.
- В локальной A/B-проверке фиксированный RU с временными метками был примерно
  на **18% быстрее** сопоставимого Auto: 2 740 против 3 331 мс. Auto остаётся
  режимом по умолчанию, потому что удобнее для многоязычной диктовки, а одного
  узкого теста недостаточно для смены настройки для всех пользователей.
- Выключение временных меток ускорения не дало: Auto — 3 698 мс, RU —
  2 769 мс. Текущий профиль `beam=1`, `int8`, 8 CPU-потоков, VAD и постоянный
  worker уже соответствует выбранному профилю малой задержки.
- Это результат одного компьютера и текущего профиля, без гарантии такой же
  скорости на другом оборудовании.

## Что ещё не считается доказанным

Автоматические проверки и установка пройдены, но ручная приёмка новой версии и
холодный запуск после перезагрузки ещё не завершены. До release нужны:

1. Вручную проверить Notepad, браузер, Проводник и Electron-приложение. Для
   Notepad отдельно подтвердить, что длинная диктовка вставляется целиком, а не
   превращается в первое слово и последовательность точек.
2. Проверить standard/elevated app, UAC secure desktop и запуск самого VoiceType
   без elevation.
3. Проверить смену focus во время длинной вставки, terminal/newline/tab и browser
   omnibox. Диктовка является вводом текста в выбранное пользователем поле;
   запрет shell относится к VoiceType Control, а не к содержимому диктовки.
4. UIA-вызов сторонней библиотеки теоретически может зависнуть. Пятисекундный
   watchdog не использует поздний результат, сбрасывает доверие к вставке и
   single-flight не накапливает новые вызовы. Жёсткая остановка зависшего
   COM-call всё ещё потребует отдельного worker process и остаётся
   release-hardening gate.
5. Отдельный opt-in Chromium-пробник безопасно выявил provider-особенность
   `ScrollIntoView → Select → read-back`, но два последних запуска Chrome не
   отдали уникальный набор локальных тестовых полей UI Automation. Поэтому
   Chromium-стенд пока не считается полностью пройденным release-gate; при
   любой неопределённости редактор отказывает до изменения текста.
6. Вручную пройти все шесть страниц нового интерфейса, клавиатурную навигацию,
   компактную прокрутку, три режима и RAM-обратную связь.
7. Вручную принять установленный candidate, затем перезагрузить Windows и
   подтвердить автозапуск одной копии из `%LOCALAPPDATA%\Programs`.
8. Для публичного бинарного релиза остаются финальная проверка состава dist,
   проверка лицензий/SBOM, антивирусная проверка и в дальнейшем code signing.

Ручные шаги отмечаются только по факту в
[`MANUAL_ACCEPTANCE_CHECKLIST.md`](MANUAL_ACCEPTANCE_CHECKLIST.md).

- обязательные многогигабайтные модели;
- полноценный редактор шаблонов и модельный менеджер;
- окончательная подпись/автообновление и коммерческая упаковка.
